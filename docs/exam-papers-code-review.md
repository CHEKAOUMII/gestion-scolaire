## 1. الخلاصة

الصفحة مبنية بشكل جيد كواجهة تطبيق (HTML رقيق + منطق في `js/pages/`) ومتوافقة مع نمط الصفحات الأخرى (مثل `support-sessions` / `grades-sheets`).

**المنطق الأساسي:**
- مصفوفة **قسم × فرض**
- التقويم التشخيصي يظهر في **الدورة الأولى فقط**
- الحفظ في `localStorage` بمفتاح `examPapers_handovers_v2`
- مرجع الأساتذة/المواد/الجدول عبر `window.api` (IPC)

**الحكم:** جاهزة كـ MVP داخلي، لكن فيها نقاط يجب إصلاحها قبل الاعتماد الإنتاجي (خصوصًا الاستيراد + تطابق المواد + مصدر عدد الفروض).

## 3. مشاكل / مخاطر

### 3.1 عالية الأولوية

#### 1) استيراد JSON غير محصّن
- لا تحقق من شكل السجل (`schoolYear`, `examId`, `teacherId`, …).
- الدمج بالمعرّف فقط: `if (h.id && !ids.has(h.id))`.
- `data-delete="${h.id}"` **بدون تهريب** → ملف مستورد خبيث قد يكسر الـ DOM / XSS.
- يمكن حقن سجلات سنوات أخرى أو بيانات تالفة في `localStorage`.

**الموقع المقترح للإصلاح:** `importJSON`, `renderLog` في `js/pages/exam-papers.js`.

#### 2) Fallback الأقسام خطير
```js
// إذا لم يُعثر على تطابق في الجدول الزمني
return classes.getAll(...) // كل أقسام المؤسسة
```
قد يعرض أقسامًا غير مسندة للأستاذ ويُحفظ استلام خاطئ.

**الموقع:** `getAssignedSections`.

#### 3) `FROUD_BASE` ثابت يدويًا
- عدد الفروض مضمّن في الصفحة (رياضيات 3، فرنسية 4، …).
- لا يرتبط بـ `taqwim-core` / المذكرة 142 / مستوى القسم.
- أي اختلاف في الواقع التربوي = أعمدة فروض خاطئة.

**الموقع:** ثابت `FROUD_BASE` + `froudCount()`.

---

### 3.2 متوسطة الأولوية

#### 4) مطابقة المادة للأساتذة حرفيّة
```js
teachers.filter((t) => (t.subject || '') === subject)
```
بينما قائمة المواد تمر عبر `normalizeSubjectName`. إن كانت `t.subject` غير مطبّعة، قائمة الأساتذة تفرغ  
(نفس نمط `support-sessions`، لكنه هش).

#### 5) التصدير لا يحترم السنة الجارية
- `handovers: loadRecords()` يصدّر **كل** السنوات، رغم أن الواجهة تعمل على سنة واحدة.

#### 6) الملاحظات تُنسخ لكل الأعمدة المحفوظة دفعة واحدة
- نفس `notes` تُكتب لكل فرض تم حفظه في نفس النقرة — قد لا يكون مقصودًا.

#### 7) لا مسار ترحيل من v1
- المفتاح الآن `examPapers_handovers_v2`.
- بيانات `examPapers_*_v1` القديمة (إن وُجدت) لن تُقرأ.

#### 8) الحذف عبر تفريغ الخانات
- حفظ عمود بلا خانات محددة = حذف السجل دون تأكيد خاص بهذا العمود  
  (يوجد تأكيد فقط لحذف الصف من السجل).

| فحص | النتيجة |
|-----|---------|
| أسرار / مفاتيح ثابتة | لا |
| `eval` / shell | لا |

| XSS عبر الاستيراد (`id`) | **نعم — يحتاج إصلاح** |
| تحقق إدخال الاستيراد | ضعيف |

## 5. توصيات مرتبة

1. **تهريب `h.id`** (وأي خاصية تُحقن في HTML) + التحقق من مخطط الاستيراد ورفض الحقول غير المتوقعة.
2. **تقييد الاستيراد/التصدير** على `schoolYear` الحالية (أو خيار واضح «كل السنوات»).
3. **إزالة fallback «كل الأقسام»** أو جعله صريحًا بزر «إضافة قسم يدويًا».
4. **توحيد عدد الفروض** مع مصدر واحد (core / circular) بدل `FROUD_BASE` المحلي.
5. **مطابقة المادة** بـ `normalizeSubjectName` على `t.subject` أيضًا.
6. **ترحيل اختياري** من مفاتيح v1 إن وُجدت بيانات قديمة.
7. **تأكيد قبل حذف** سجل عند تفريغ عمود كامل.

### نموذج السجل (handover record)

```js
{
  id,                // string uid
  schoolYear,        // e.g. "2025/2026"
  session,           // 1 | 2 (Number)
  subject,
  teacherId,
  teacherName,
  examId,            // e.g. "diag" | "s1_fk1"
  examKind,          // "diagnostic" | "fk"
  examLabel,
  assignedSections,  // string[]
  receivedSections,  // string[]
  status,            // "received" | "partial"
  handoverDate,      // YYYY-MM-DD
  notes,
  recordedAt         // ISO
}
```

### مفاتيح التخزين

| المفتاح | الاستخدام |
|---------|-----------|
| `examPapers_handovers_v2` | سجلات التسليم في `localStorage` |
| `examPapers_backup_v2` | حقل `format` في ملف التصدير JSON |
