Exact placement inside the bar: **first child of `.header-right`, before `#theme-toggle`** (RTL: near the start of the right cluster, next to global actions). Use a scoped host wrapper `.orientation-topbar-actions` so styling stays contained.

## Chosen approach: Option B (relocation source)

Keep **one** static `#print-btn` in the title-row markup as a **relocation source**. After `setupUnifiedHeader()` runs, the helper **moves** that existing node into `.header-right`.

Why Option B over "create-only":

- Preserves the `#print-btn` id and any bound listener (move, not clone).
- Keeps the HTML "exactly one `#print-btn`" contract, so the test's count assertion stays meaningful.
- Mirrors the existing precedent in `js/pages/student-profile.js:114` (re-attach page actions after unify). Note: that page re-attaches into `.page-title-row`; this task is the **first** to inject into the regenerated `.header-right`, so the post-unify guard (below) is mandatory.

## Why this needs care

`setupUnifiedHeader()` (`js/utils.js:2180`) **replaces** `header.innerHTML` once `data-unified-header` is not yet set. `.header-right` is destroyed and rebuilt. Therefore, unlike today (button survives because it lives in the un-wiped title row), a button placed in `.header-right` **must** be (re)mounted **after** unify.

Rules:

1. Do **not** rely on a static print button inside `.header-right` markup — it will be wiped.
2. Mount **after** `setupUnifiedHeader` has run; gate the retry on `header.dataset.unifiedHeader === 'true'` (or `.header.dashboard-topbar` present), **not** on title-row presence.
3. **Move** the existing `#print-btn` node into the sticky header (preserves id + listeners); only create if it is missing entirely.
4. On every `ensurePrintInTopBar` call, remove stray `.ux-print-preview-btn` / `aria-label="معاينة الطباعة"` nodes that are **not** the single sticky-bar button.

- Moving print buttons on other pages (grades, absences, student profile, etc.).
