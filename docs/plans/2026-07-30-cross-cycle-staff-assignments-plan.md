# خطة دعم تعيينات الموظفين العابرة للأسلاك

**التاريخ:** 2026-07-30  
**الحالة:** قيد التنفيذ — طبقة الهوية والتعيينات والمراجعة واستعمال الزمن وحصص الدعم منفذة، والربط التشغيلي الكامل ما زال متبقيًا
**مرتبطة بـ:** [خطة استكمال دعم الأسلاك التعليمية](2026-07-30-cycle-scoping-remaining-roadmap.md)

## الهدف

فصل هوية الموظف عن تخصصه الإداري وعن تعييناته التدريسية الفعلية، بحيث يمكن لأستاذ واحد أن يدرّس في `secondary_collegial` و`secondary_qualifiant` خلال نفس الموسم دون تكرار ملفه أو منع استيراد النقط. الإداريون والمدير مشتركون على مستوى المؤسسة، بينما المدير أو المسؤول المخول هو صاحب القرار النهائي في مكان عمل الأستاذ الفعلي.

## الدليل المتاح

| المصدر | ما يثبته |
|---|---|
| `D:\secondaire\10401E_20260728.xml` | ملف `DsAgentExport` يحوي سجلات `ACTIVITE` مع `PPR` و`CD_ETAB` و`CD_CYCLE` و`CD_FONC` و`CD_MODAFFE` وتواريخ التعيين. |
| `D:\secondaire\ListEleve_20260730.xlsx` | الأقسام الإعدادية الفعلية: `1APIC-*` و`2APIC-*` و`3APIC-*`. |
| `D:\secondaire\Export_10401E_1APIC-2_INSTRUCTION ISLAMIQUE_28072026160612.xlsx` | تعيين تدريس عملي: الأستاذ + المادة + القسم + المستوى + الدورة + السنة. |

لا تُستنتج صلاحية الأستاذ للتدريس من تخصصه أو من `CD_CYCLE` وحده. ملف النقط أو جدول الحصص أو الإدخال اليدوي هو دليل التعيين الفعلي.

## قرارات غير قابلة للتفاوض

1. جدول `teachers` يمثل الشخص مرة واحدة على مستوى المؤسسة؛ `PPR` هو الهوية الخارجية المستقرة عند توفره.
2. التخصص/الوظيفة الإدارية (`CD_FONC`) و`CD_CYCLE` في ملف الوزارة **بيانات مصدرية**، وليسا حظرًا للتدريس في سلك آخر.
3. التعيين التدريسي هو سجل مستقل ومؤرخ بالسنة، ويحمل `cycle_code` والمستوى والقسم والمادة.
4. يحق للأستاذ امتلاك أكثر من تعيين في السنة نفسها، بما فيها تعيينان في سلكين مختلفين.
5. المدير أو المستخدم المخول بدور `principal` أو `admin` يعتمد ويعدل التعيين الفعلي للأستاذ؛ قرار المؤسسة المعتمد يتقدم على كل قيمة مصدرية من ملف الوزارة.
6. الموظف الإداري والمدير مشتركان على مستوى المؤسسة (`institution_wide`) ويظهران في جميع الأسلاك؛ لا يكرران ولا يفرضان `cycle_code` إلا إذا كان للموظف أيضًا تعيين تدريس مستقل.
7. لا تُنشأ هوية جديدة بسبب اختلاف الاسم بين XML وملف النقط. تُطابق الهوية بـ `PPR` أولًا ثم مراجعة الاسم عند غياب `PPR`.
8. لا يكتب استيراد النقط تعيينًا نهائيًا تلقائيًا عند غموض تطابق الأستاذ؛ ينشئ مرشحًا قابلًا للمراجعة فقط.

## نموذج البيانات المقترح

### `teachers` — يبقى على مستوى المؤسسة

لا تضف `cycle_code` إلى جدول الموظفين. الحقول المرجعية المطلوبة:

```text
id
ppr                    -- UNIQUE عند عدم الفراغ
full_name
source_function_code   -- CD_FONC، اختياري
source_assignment_mode -- CD_MODAFFE، اختياري
source_cycle_code      -- آخر CD_CYCLE وارد، للعرض/التتبع فقط
scope_type              -- institution_wide للإداريين، teaching_assignment للأساتذة
source_updated_at
```

### `teacher_teaching_assignments` — جدول جديد

```sql
CREATE TABLE teacher_teaching_assignments (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    teacher_id INTEGER NOT NULL REFERENCES teachers(id),
    school_year TEXT NOT NULL,
    cycle_code TEXT NOT NULL,
    level_code TEXT,
    section TEXT,
    subject_code TEXT,
    subject_label TEXT,
    source TEXT NOT NULL,
    source_file_name TEXT,
    decision_source TEXT NOT NULL DEFAULT 'import_suggestion',
    decided_by_user_id INTEGER,
    decided_at TEXT,
    confidence TEXT NOT NULL DEFAULT 'review_required',
    is_active INTEGER NOT NULL DEFAULT 1,
    created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(teacher_id, school_year, cycle_code, level_code, section, subject_code)
);

CREATE INDEX idx_teacher_assignments_cycle_year
    ON teacher_teaching_assignments(cycle_code, school_year);
CREATE INDEX idx_teacher_assignments_teacher_year
    ON teacher_teaching_assignments(teacher_id, school_year);
```

`confidence` يقبل: `confirmed` أو `review_required` أو `rejected`.

`decision_source` يقبل: `import_suggestion` أو `principal_decision` أو `admin_decision` أو `manual_assignment`. لا يصبح التعيين نافذًا تشغيليًا إلا عند `confidence = 'confirmed'`، ويُسجل صاحب القرار وتاريخه عندما يعتمد المدير أو المسؤول التعيين.

## خريطة رموز المصدر

لا تُشفّر هذه الخريطة في الإنتاج قبل تأكيدها من وثيقة Masar أو مسؤول المؤسسة:

| رمز مصدر الوزارة | الهدف المحتمل | الحالة |
|---|---|---|
| `2A` | `secondary_collegial` | يحتاج تأكيدًا رسميًا |
| `3A` | `secondary_qualifiant` | يحتاج تأكيدًا رسميًا |
| فارغ | `institution_wide` | مؤكد كمعالجة آمنة |

حتى التأكيد، يخزن المستورد الرمز الخام في `source_cycle_code` ولا يستخدمه لتغيير تعيين تدريسي أو لمنع عملية استيراد.

## المهام

- [x] **تثبيت خريطة مستويات الأقسام** في مصدر واحد: `1APIC` و`2APIC` و`3APIC` → `secondary_collegial`، مع المقابل التأهيلي الموجود. → التحقق: تُصنف عينة أقسام APIC وBAC بصورة صحيحة، ولا يُخمن سلك لقسم مجهول.
- [x] **إنشاء ترحيل ومخزن `teacher_teaching_assignments`** مع عمليات قراءة/إضافة/تحديث مقيدة بالسنة والسلك. → التحقق: يمكن حفظ أستاذ واحد في تعيينين مختلفين بلا تكرار صف `teachers`.
- [x] **توسيع استيراد `agent_xml`** لحفظ الموظف بـ `PPR` وتخزين بيانات `ACTIVITE` الخام كبيانات مصدرية فقط. → التحقق: إعادة استيراد XML لا تنشئ نسخًا مكررة، والسجل بلا `CD_CYCLE` يبقى مؤسسيًا.
- [x] **إنشاء مرشحات تعيين من استيراد النقط** من `teacher + subject + level + section + school_year`. → التحقق: تصدير `1APIC-2` للتربية الإسلامية ينشئ مرشحًا بسلك إعدادي دون فحص تخصص الأستاذ.
- [x] **إضافة واجهة مراجعة وإدارة التعيينات** تعرض المرشحات المؤكدة والغامضة، وتسمح للمدير أو `admin` باعتماد التعيين أو نقله للإعدادي أو التأهيلي أو حسم مطابقة اسم النقط بهوية محددة أو تصنيف الموظف مؤسسيًا. → التحقق: المطابقة الغامضة تظهر في قائمة مراجعة، ولا تُربط قبل اختيار المستخدم، ويسجل القرار ومصدره وصاحبه وتاريخه.
- [x] **عرض الموظفين حسب النطاق**: الإداريون والمدير يظهرون في كل سلك بوصف `مشترك على مستوى المؤسسة`؛ الأساتذة يظهرون فقط عند وجود تعيين تدريسي مؤكد في السلك الحالي. → التحقق: الإداري لا يتكرر، وأستاذ السلك الآخر لا يظهر دون تعيين فعلي.
- [ ] **ربط جدول الحصص والغياب والحراسة** بتعيينات التدريس بدل الاعتماد على `teachers.subject` أو الاسم الحر. → **منجز جزئيًا:** `timetable_data` أصبح مفتاحه `(school_year, cycle_code)`، وحصص الدعم تحمل سلك القسم ولا تُسجل لأستاذ بلا تعيين مؤكد؛ ما زال ربط غياب الأساتذة والتقرير اليومي وكاشف تعارض الحراسة مطلوبًا. → التحقق النهائي: أستاذ واحد يمكن تعيينه في السلكين ولا يُمنع من الظهور في أي منهما؛ كاشف التعارض يمنع حجزه في نفس الحصة مرتين.
- [x] **تقييد صلاحيات القراءة والكتابة**: بيانات الموظف مؤسسية، وتعييناته مرشحة بالسلك النشط عند العمل التشغيلي. → التحقق: جلسة إعدادية لا تعدل تعيينًا تأهيليًا بالمعرف المباشر.
- [x] **تحديث عقود المزامنة والنسخ الاحتياطي** للجدول الجديد مع `cycle_code` مطلوب. → التحقق: مزامنة جهازين لا تنقل تعيينًا إلى سلك آخر، والاستعادة تحافظ على التعيينات المؤسسية والعابرة للأسلاك.
- [ ] **اختبارات الانحدار والإطلاق**. → **منجز جزئيًا:** اختبارات التعيينات، قائمة المراجعة، ترحيل مفتاح جدول الحصص، وعقود السلك تمر؛ لا يُرفع `secondary_collegial` إلى `supported` قبل اكتمال عزل الغياب والتقارير والحراسة والامتحانات.

## قواعد الاستيراد

### ملف الوزارة `DsAgentExport`

1. اقرأ كل `ACTIVITE`.
2. ابحث عن الموظف بـ `PPR`.
3. أنشئ أو حدّث ملف الموظف المؤسسي فقط.
4. احفظ الرموز الخام والتواريخ من المصدر.
5. لا تنشئ تعيين مادة/قسم من `CD_CYCLE` وحده.
5. أنشئ اقتراح تعيين فقط إن كانت خريطة رمز الوزارة مؤكدة؛ يبقى الاقتراح قابلًا للتعديل من المدير.
6. صنف المدير والإداريين `institution_wide`، ولا تنشئ لهم تعيينًا تدريسيًا تلقائيًا.
7. لا ترفض سجلًا لأن `CD_CYCLE` يختلف عن السلك النشط.

### ملف النقط

1. استخرج `teacher`, `subject`, `level`, `section`, `schoolYear`.
2. استخرج `cycle_code` من القسم/المستوى، لا من تخصص الموظف.
3. ابحث عن الأستاذ بالهوية المرجعية إن توفرت؛ وإلا استعمل مطابقة الاسم مع واجهة مراجعة.
4. أنشئ مرشح تعيين عند تطابق مؤكد؛ لا يصبح مؤكدًا إلا بقرار المدير/المسؤول أو بدليل موثق من جدول الحصص.
5. يسمح للمدير بنقل التعيين أو تعديله حتى لو خالف `source_cycle_code` أو تخصص الأستاذ الوارد من ملف الوزارة.
6. ارفض كتابة النقط إن كان السلك النشط لا يطابق سلك القسم بعد تفعيل السلكين.

## معايير القبول

- الأستاذ المؤهل تأهيليًا يستطيع تدريس `1APIC-2` واستيراد نقطه دون خطأ سلك.
- الأستاذ نفسه يظهر مرة واحدة في دليل الموظفين، مهما تعددت تعييناته.
- يمكن تعيين الأستاذ نفسه في `1APIC-2` وفي قسم تأهيلي في الموسم نفسه.
- الموظف الإداري والمدير يظهران في كل سلك مرة واحدة بوصفهما مشتركين على مستوى المؤسسة.
- المدير أو `admin` يستطيع اعتماد أو نقل تعيين أستاذ بين السلكين، ويظهر القرار في سجل المراجعة.
- لا يُفترض أن `2A` أو `3A` يحددان صلاحية التدريس قبل تأكيد خريطة المصدر.
- لا تتداخل التعيينات أو النقط أو الحصص بين السلكين.
