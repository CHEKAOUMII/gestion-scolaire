# Refactor Plan: js/ux-enhancements.js

## Overview

The file is ~1316 lines of shared UX utilities including theme management, dialog system, keyboard shortcuts, quick navigation, print preview, auto-updater UI, letterhead builder, palette utilities, and sync status indicator. It mixes concerns, has duplicated patterns, and uses module-level globals that could be better encapsulated.

## Issues Identified

### 1. **Multiple DOMContentLoaded listeners scattered throughout** (lines 490-494, 1290-1295, 1307-1311)

Three separate blocks register DOM-ready handlers, making initialization order hard to follow.

### 2. **Module-level globals for state** (lines 498-501, 890, etc.)

`_printPreviewModal`, `_printPreviewOptions`, `_printPreviewLandscape`, `_savedThemeBeforePrint`, `_updateBanner` are all file-scoped globals. They work but make testing harder and pollute the module scope.

### 3. **Duplicated escape/HTML encoding logic** (lines 674-678 vs 1037-1042)

`openPrintPreview` has an inline `_esc` function, while `buildLetterheadHTML` has a similar `e` function. These should be unified.

### 4. **Duplicated headerTools close logic** (lines 454-460)

The `headerTools instanceof HTMLDetailsElement` check and `headerTools.open = false` pattern appears multiple times in the click handler.

### 5. **Duplicated closeDialog calls for modals** (lines 277-278)

`closeDialog(shortcutsModal)` and `closeDialog(backupModal)` could be looped.

### 6. **Duplicated aria-hidden and class toggling in quick nav** (lines 338-342, 374-376)

The pattern of setting `aria-hidden`, `aria-expanded`, and class toggles is repeated.

### 7. **Long function: `openPrintPreview`** (~170 lines, lines 587-755)

This function does too much: modal creation, content cloning, canvas snapshot, letterhead building, theme switching. Should be broken into smaller steps.

### 8. **Duplicated print/PDF execution patterns** (lines 832-878)

`_executePrintFromPreview` and `_exportPdfFromPreview` share nearly identical structure: capture sheet → close preview → enable print mode → wait → call API → disable print mode.

### 9. **Magic strings for selectors** (lines 614-616)

The long selector string for elements to strip from print clone is a maintenance hazard.

### 10. **Duplicated DOMContentLoaded registration pattern**

The file uses `if (document.readyState === 'loading') ... else ...` three times. A single helper or unified init sequence would be cleaner.

### 11. **Inconsistent naming**

Some functions use `Global` suffix (`closePrintPreviewGlobal`), others don't. Private functions use `_` prefix but not consistently (e.g., `_hasCanvases` is local, `_esc` is local, but `_forceLightThemeForPrint` is exposed).

### 12. **`window.UXEnhancements` exposes private functions** (line 1310-1311)

`forceLightThemeForPrint` and `restoreThemeAfterPrint` are exposed despite being prefixed with `_`, suggesting they were meant to be private.

## Refactoring Steps

### Step 1: Extract shared utilities

- Create a single `escapeHtml` function to replace both `_esc` and `e`
- Create `closeHeaderTools()` helper to deduplicate the HTMLDetailsElement closing logic
- Create `setQuickNavAria(panel, toggle, isOpen)` helper

### Step 2: Consolidate initialization

- Replace all three DOMContentLoaded blocks with a single unified init sequence
- Create an `initAll()` function that calls everything in order

### Step 3: Break down `openPrintPreview`

- Extract `_prepareCloneForPrint(clone, sourceEl, options)` — handles clone cleanup, canvas replacement, background forcing
- Extract `_buildLetterheadForPreview(options)` — handles the async identity fetch and header HTML generation
- Extract `_renderPreviewSheet(sheet, headerHTML, clone)` — DOM insertion logic

### Step 4: Consolidate print/PDF execution

- Create `_executeExportFromPreview(apiMethod, options)` to handle the shared flow

### Step 5: Clean up naming and exports

- Decide what's truly public vs private
- Remove `_`-prefixed functions from `window.UXEnhancements` if they're internal
- Rename `closePrintPreviewGlobal` → `closePrintPreview` (remove the `Global` suffix)

### Step 6: Reduce magic strings

- Extract the print-clone strip selectors into a constant array

## Trade-offs

| Trade-off                | Decision                                                                                                                 |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| More functions vs fewer  | Breaking into smaller functions improves readability and testability, even if it increases function count                |
| Encapsulation vs globals | Using an IIFE or module pattern would be ideal but may break existing page-level access. Keep globals but document them. |
| Exposing `_` functions   | Remove `forceLightThemeForPrint` and `restoreThemeAfterPrint` from exports since they're internal implementation details |

## Risk Assessment

- **Low risk**: Most changes are internal refactoring — extracting functions, deduplicating patterns
- **Medium risk**: Changing initialization order could affect pages that depend on specific timing. The unified init should preserve the current order.
- **No behavior changes**: All functionality must be preserved exactly.
