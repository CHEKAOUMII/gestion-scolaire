# Implementation Plan: Server-Side OTP (Lambda + DynamoDB)

**Branch**: `011-server-otp` | **Date**: 2026-03-22 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/011-server-otp/spec.md`

## Summary

Add server-side OTP publish and verify endpoints to the existing Auth Lambda, enabling device linking when devices are NOT on the same LAN. Device 1 publishes an AES-256-GCM encrypted sync config (keyed by OTP via HKDF) to DynamoDB. Device 2 verifies the OTP via Lambda and decrypts the config locally. The Lambda never sees plaintext config. A new client module (`main/linking/server.js`) handles encryption, decryption, and HTTP calls.

## Technical Context

**Language/Version**: Node.js 18 (Lambda runtime), vanilla JS (Electron main process)
**Primary Dependencies**: `@aws-sdk/client-dynamodb`, `@aws-sdk/lib-dynamodb` (Lambda); `node:crypto` (both Lambda and client); existing `@aws-sdk/client-cognito-identity`, `@aws-sdk/client-secrets-manager` (Lambda, already present)
**Storage**: DynamoDB (`pencil2-sync` table, existing) — OTP items with `PK: OTP#<massar>`, `SK: ACTIVE`
**Testing**: `npm run lint`, `npm run test:smoke` (existing); manual integration test with deployed Lambda
**Target Platform**: AWS Lambda (server); Windows Electron (client)
**Project Type**: Desktop app (Electron) + serverless backend (Lambda)
**Performance Goals**: Publish < 3s, verify < 3s (including network latency)
**Constraints**: Zero new npm dependencies in Lambda or client; end-to-end encryption; scrypt verification in Lambda without importing main-process modules
**Scale/Scope**: 1 new file, 3 modified files; 2 new Lambda routes; ~300 lines total
