# Data Model: First-Run Setup Page

**Feature**: 012-first-run-setup
**Date**: 2026-03-22

## Entities

### Institution Configuration (existing table: `institution_config`)

Singleton record (id=1) representing the school's identity and setup state.

| Field | Type | Constraints | Purpose |
|-------|------|-------------|---------|
| id | Integer | PRIMARY KEY, CHECK(id=1) | Singleton guarantee |
| massar_code | Text | - | Ministry school identifier (e.g., "M320456") |
| institution_name | Text | Optional | Display name for the school |
| setup_completed | Integer | DEFAULT 0 | 0 = not set up, 1 = setup done |
| setup_mode | Text | 'new' or 'linked' | How this device was onboarded |
| setup_device_hash | Text | - | Hardware hash of the device that performed setup |
| created_at | DateTime | DEFAULT CURRENT_TIMESTAMP | Record creation time |
| updated_at | DateTime | DEFAULT CURRENT_TIMESTAMP | Last modification time |

**State transitions**:
- Row absent → Row created with `setup_completed=0` (implicit on first query)
- `setup_completed=0` → `setup_completed=1` (on successful setup completion)
- Once `setup_completed=1`, it is never reset to 0

**Read pattern**: Queried at app startup in `main.js` to determine redirect target.
**Write pattern**: Written once during setup flow (new institution or successful OTP link).

---

### Linked Devices (existing table: `linked_devices`)

Registry of all devices associated with this institution.

| Field | Type | Constraints | Purpose |
|-------|------|-------------|---------|
| id | Integer | PRIMARY KEY AUTOINCREMENT | Row identifier |
| device_hash | Text | UNIQUE NOT NULL | Hardware-based fingerprint |
| device_name | Text | - | Human-readable device name (hostname) |
| os_platform | Text | - | Operating system (e.g., "win32") |
| app_version | Text | - | Application version at link time |
| linked_by | Text | - | How device was linked: 'setup_new', 'otp_lan', 'otp_server' |
| linked_at | DateTime | - | When device was linked |
| last_seen_at | DateTime | - | Last sync heartbeat |
| revoked_at | DateTime | - | When device was revoked (if applicable) |
| status | Text | DEFAULT 'active' | 'active' or 'revoked' |

**Write pattern (setup page)**: INSERT on new institution setup or successful OTP link.

---

### Admin User Account (existing table: `users`)

The admin account is pre-seeded by `createTables()` with id=1. The setup page UPDATES this row.

| Field | Type | Relevant to setup | Purpose |
|-------|------|-------------------|---------|
| id | Integer | Yes (always 1) | Admin is always user id=1 |
| name | Text | Yes | Set by user during setup |
| email | Text | No | Kept as default 'admin@school.local' |
| role | Text | No | Always 'admin' |
| password_hash | Text | Yes | Set from user's chosen password via `hashPassword()` |
| must_change_password | Integer | Yes | Set to 0 during setup (user explicitly chose password) |
| disabled | Integer | No | Always 0 |

**Write pattern (setup page)**: UPDATE `name`, `password_hash`, `must_change_password=0` WHERE `id=1`.

---

## Relationships

```
institution_config (1) ──── (1) linked_devices [setup device]
                   │
                   └──── (1) users [admin, id=1]
```

- `institution_config.setup_device_hash` references the `linked_devices.device_hash` of the device that performed initial setup.
- The admin user (id=1) is implicitly tied to the institution — no explicit FK since the system is single-institution.

## Validation Rules

| Entity | Field | Rule |
|--------|-------|------|
| Institution Config | massar_code | Non-empty, alphanumeric, trimmed, matches pattern `/^[A-Za-z]\d{4,8}$/` |
| Institution Config | setup_mode | Must be 'new' or 'linked' |
| Users (admin) | name | Non-empty, trimmed |
| Users (admin) | password_hash | Derived from password with min 6 characters |
| Linked Devices | device_hash | Non-empty, generated by `collectCurrentFingerprint()` |
| Linked Devices | linked_by | Must be 'setup_new', 'otp_lan', or 'otp_server' |
