# Data Model: Device Management UI

**Feature**: 014-device-management-ui
**Date**: 2026-03-23

## Entities

### 1. Institution Config (read-only from UI)

The device management UI reads this entity but does not modify it. It was created during first-run setup (Phase 7.5).

| Field | Type | Description |
| ----- | ---- | ----------- |
| massar_code | Text | Ministry school identifier (e.g., "M320456"). Unique per institution. |
| institution_name | Text (nullable) | Optional display name for the school. |
| setup_completed | Boolean | Whether first-run setup has been completed. |
| setup_mode | Text | How this device was set up: `'new'` (origin device) or `'linked'` (joined via OTP). |
| setup_device_hash | Text | Device hash of the device that performed setup. |

**Singleton**: Always exactly one row (id=1).

**UI usage**: Displayed in the "Current Device Info" section. The `setup_completed` flag gates whether the device management section renders at all.

---

### 2. Linked Device

Represents a device registered in the institution's device fleet.

| Field | Type | Description |
| ----- | ---- | ----------- |
| device_hash | Text (unique) | Stable hardware-derived hash (64 hex chars). Primary identifier. |
| device_name | Text (nullable) | Hostname of the device at link time. |
| os_platform | Text (nullable) | OS platform string (e.g., `'win32'`, `'darwin'`, `'linux'`). |
| app_version | Text (nullable) | Application version at link time. |
| linked_by | Text | How the device was linked. One of: `'setup_new'`, `'otp_lan'`, `'otp_server'`. |
| linked_at | DateTime | When the device was first linked. |
| last_seen_at | DateTime (nullable) | Last sync heartbeat timestamp. |
| revoked_at | DateTime (nullable) | When the device was revoked (null if active). |
| status | Text | Current status: `'active'` or `'revoked'`. |

**Display mapping for `linked_by`**:

| Value | Arabic Label |
| ----- | ------------ |
| `setup_new` | إعداد جديد |
| `otp_lan` | ربط محلي |
| `otp_server` | ربط عبر السيرفر |

**Display mapping for `status`**:

| Value | Arabic Label | Visual |
| ----- | ------------ | ------ |
| `active` | نشط | Green badge |
| `revoked` | ملغى | Red badge |

**State transitions**:

```
active ──[admin revokes]──► revoked
```

Revocation is one-way. There is no reactivation flow in scope.

### 3. OTP (One-Time Password)

Represents a time-limited linking code generated by an admin.

| Field | Type | Description |
| ----- | ---- | ----------- |
| otp (plaintext) | Text (6 digits) | Only available at generation time. Never stored in plaintext. |
| otp_hash | Text | Scrypt hash of the OTP code. |
| massar_code | Text | Institution this OTP is for. |
| created_by_device | Text | Device hash of the admin who generated the OTP. |
| expires_at | DateTime | Absolute expiry timestamp (10 minutes after creation). |
| used_by_device | Text (nullable) | Device hash that consumed the OTP. |
| used_at | DateTime (nullable) | When the OTP was consumed. |
| status | Text | Current status: `'active'`, `'used'`, or `'expired'`. |

**State transitions**:

```
active ──[10 min elapsed]──► expired
active ──[device verifies]──► used
active ──[admin cancels]───► expired
active ──[new OTP generated]──► expired (replaced)
```

**UI-relevant properties** (returned by `getOtpStatus`):

| Property | Type | Description |
| -------- | ---- | ----------- |
| active | Boolean | Whether an OTP is currently active. |
| expiresAt | ISO-8601 string | When the OTP expires. Used to compute countdown. |
| remainingSeconds | Number | Seconds remaining (convenience, but UI should recompute from `expiresAt`). |

---

### 4. Current Device (computed, not stored)

Represents the device the user is currently operating. Computed at runtime from hardware fingerprinting.

| Property | Type | Description |
| -------- | ---- | ----------- |
| deviceHash | Text (64 hex chars) | Stable hardware-derived hash. Used to identify this device in the linked_devices table. |
| deviceName | Text | OS hostname. |
| platform | Text | OS platform string. |
| appVersion | Text | Current application version. |

**UI usage**: Displayed in the "Current Device Info" section. The `deviceHash` is compared against each row in the linked devices table to identify and highlight the current device's row.

---

## Relationships

```
Institution Config (1) ──── (many) Linked Devices
                     └──── (many) OTPs

Current Device ──matches── one Linked Device row (by device_hash)
```

- Each institution has many linked devices.
- Each institution can have at most one active OTP at a time.
- The current device always corresponds to exactly one row in linked_devices (matched by `device_hash`).
