# Print / PDF Preview Modifications

> Hard-won rules for this app's print pipeline. Read BEFORE touching any printable sheet's CSS/JS.

---

## 0. First Rule: Reload After Inline-CSS Edits

| Fact | Consequence |
|------|-------------|
| Page styles live in inline `<style>` in the `.html` | Editing the file does NOT update an already-open page |
| `npm run dev` watches `tailwind-output.css` ONLY, not HTML | No hot-reload for HTML/inline CSS |
| Print path A clones the **live DOM** | Old DOM = old styles in PDF too |

> 🔴 After any inline-CSS/HTML edit: user must **reload the page (Ctrl+R / Ctrl+Shift+R)** or renavigate, then re-generate + re-export. If "nothing changed", suspect stale page FIRST.

## 1. The Two Print Paths (js/print-system.js)

| Path | API | Mechanism | Used by |
|------|-----|-----------|---------|
| **A** | `PrintSystem.preview(opts)` | Clones live DOM → modal `.ux-pp-sheet` → prints current window `#ux-print-root` | absence-weekly & most DOM sheets |
| **B** | `PrintSystem.window(opts)` | Builds HTML string → temp file → hidden BrowserWindow (`main/print-window.js`) | grade sheets, certificates, complex reports |

- Path A adds the school **letterhead automatically** via `reports.getIdentity()` unless `noHeader:true`.
- Path A export uses Electron `system:printToPDF` / `system:printCurrentWindow` (main/ipc/system.js).

## 2. 🔴 THE BIG TRAP: Global Print CSS Overrides

`css/tailwind-output.css` (compiled from `tailwind-input.css`) contains **print-scope rules** that only activate during printing and **beat page styles** via `!important` + an `#ux-print-root` ID:

```css
body.ux-printing-active #ux-print-root th {
    background: #1a5276 !important;   /* dark navy header */
    color: #fff !important;
    padding: 5px 8px !important;
}
body.ux-printing-active #ux-print-root td { padding:5px 8px !important; border-bottom:1px solid #e5e7eb !important; }
body.ux-printing-active #ux-print-root tbody tr:nth-child(even) { background:#f5f8fa !important; }
```

**Symptom:** screen looks correct, but PDF/preview shows dark navy headers, thick padding, forced zebra — NOT what the page CSS says.

**Why grep misses it:** color is `#1a5276` (not the page's palette) and selector is under the print scope. Search for `ux-print-root th` / `ux-printing-active`, not the color.

### Fix pattern — override in the page's inline `<style>`

Match BOTH scopes (preview + real print), use `!important`, and place the block **last** in the page `<style>` (it loads after the `tailwind-output.css` link):

```css
.ux-pp-sheet .aw-table thead th,
body.ux-printing-active #ux-print-root .aw-table thead th {
    background: var(--aw-head) !important;
    color: var(--aw-ink) !important;
    padding: 1px !important;
    border: 0.75px solid var(--aw-line) !important;
}
/* repeat for th.aw-day, th.aw-subject, td, tbody tr:nth-child(even) td, .aw-day-sep */
```

| Rule | Reason |
|------|--------|
| Include `#ux-print-root` in selector | Needed to match the ID specificity of the global rule |
| Also include `.ux-pp-sheet` selector | Preview modal isn't inside `#ux-print-root` |
| Keep `!important` | Global rule uses it |
| Reference `.aw-sheet` CSS vars freely | Cells are descendants of `.aw-sheet`; vars resolve |

> Do NOT edit `tailwind-output.css` directly — it's regenerated by `npm run css:build`. Override in the page, or fix the source `tailwind-input.css` if a global change is truly intended.

## 3. Calling preview correctly

```js
PrintSystem.preview({
    contentSelector: '#sheet',        // clone ONLY the sheet
    title: 'ورقة الغياب الأسبوعية',
    pageSize: 'A4',
    landscape: false                  // portrait
});
```

| Option | Effect |
|--------|--------|
| `contentSelector: '#sheet'` | Clones just that element AND **skips `_cleanClone`** |
| (omit contentSelector) | Clones `.main-content` and runs `_cleanClone`, which **hides empty last-child cells** — breaks intentionally blank marking/total columns |
| `landscape` | `false` = portrait, `true` = landscape |
| `noHeader: true` | Skip auto letterhead |

> 🔴 If your sheet has empty cells (attendance marks, totals), ALWAYS pass `contentSelector` to avoid `_cleanClone` deleting them.

## 4. Fit-to-Page: use CSS-var scaling, NOT zoom

| Approach | Works in printToPDF? |
|----------|----------------------|
| CSS `zoom` | ❌ Unreliable in Electron PDF export |
| `transform: scale()` | ❌ Leaves original layout box → blank pages |
| **`--scale` var on real metrics** (`calc(Xpx * var(--scale,1))`) | ✅ Real reflow, honored in PDF |
| Native `scale` option | ✅ but `system:printToPDF` handler does NOT forward it (would need main-process change) |

### Pattern
Apply a custom prop to the sheet's vertical metrics and font sizes:
```css
th.aw-subject { height: calc(140px * var(--aw-scale, 1)); }
td.aw-cell    { height: calc(20px  * var(--aw-scale, 1)); }
table.aw-table{ font-size: calc(0.72rem * var(--aw-scale, 1)); }
```
Then set `sheet.style.setProperty('--aw-scale', factor)`. Keep **column widths as %** so the table still fills page width while only height compresses.

## 5. Page-count estimate (A4 portrait)

```js
const PX_PER_MM = 96 / 25.4;
const PRINT_W_PX = Math.round((210 - 2*4.06) * PX_PER_MM); // ≈763  (0.16in L/R margins)
const PRINT_H_PX = Math.round((297 - 2*5.08) * PX_PER_MM); // ≈1084 (0.2in T/B margins)
const LETTERHEAD_PX = 155; // estimate; subtract from page-1 capacity
```
- Measure by cloning `.aw-sheet` into an offscreen wrapper of width `PRINT_W_PX`, set `--aw-scale`, read `scrollHeight`.
- Label the result as **approximate** (`≈`) — letterhead height varies with the school logo.
- `<thead>` repeats per page automatically in Chromium print.

## 6. Layout tips for dense sheets

| Need | Technique |
|------|-----------|
| Many columns fit portrait width | `table-layout: fixed` + dynamic `<colgroup>` with % widths |
| Narrow column labels | Vertical text: `writing-mode: vertical-rl; text-orientation: mixed; transform: rotate(180deg)` |
| Backgrounds render in PDF | `-webkit-print-color-adjust: exact; print-color-adjust: exact` on the sheet (export sets `printBackground:true`) |
| Print-friendly colors | Light header fills + dark text + thin (`0.75px`) borders; avoid heavy dark fills |
| Empty-state padding leaking in | Remove shared `.page-empty-state` class (`50px 20px`) from the container when rendering real content |

---

## 7. Debug checklist (colors/layout wrong in PDF)

1. Reload page — confirm the **on-screen** sheet already looks right. If not, it's stale CSS, not print.
2. Open DevTools on the preview modal → inspect a `<th>`/`<td>` → check **Styles** panel for `!important` rules from `tailwind-output.css` (line ~3900+, `ux-print-root`).
3. If a global print rule wins → add a page-scoped override (§2) for both `.ux-pp-sheet` and `#ux-print-root`.
4. Empty cells vanishing → add `contentSelector` (§3).
5. Fit/scale not applying to PDF → use `--scale` var, not `zoom` (§4).
